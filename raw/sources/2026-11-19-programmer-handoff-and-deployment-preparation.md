## Суть завдання та цілі на наступний етап
1. **Підготовка репозиторію на GitHub для зовнішнього програміста магазину:**
   - Код має бути повністю автономним, чистим та готовим до швидкого запуску.
   - Надання чітких варіантів розгортання: Docker/docker-compose або системний сервіс systemd на сервері магазину.
2. **Архітектура ендпоінтів та інтеграція з OpenCart:**
   - Визначити схему роботи між квізом та OpenCart:
     - Варіант 1: Робота через існуючий стандартний маршрут OpenCart `POST /index.php?route=checkout/cart/add`.
     - Варіант 2 (Рекомендований): Підготовка легкого контролера для OpenCart (`add_bulk`), який приймає масив обраних товарів та додає весь бокс в один клік у поточну сесію покупця.
3. **Маршрутизація та розв'язання проблем CORS/Cookies:**
   - Оптимальне розміщення сервісу через Reverse Proxy на основному домені (наприклад `raceexpert.com.ua/quiz/` або `raceexpert.com.ua/box/`), що усуває проблеми з міжсайтовими cookies (`OCSESSID`) та блокуванням браузерами.
4. **Синхронізація залишків товарів:**
   - Організація регламентного оновлення товарних каталогів або прямих запитів до MySQL магазину.

## Фінальні вимоги до пакету передачі репозиторію
1. Репозиторій на GitHub містить 100% необхідних файлів для автономного запуску розробником.
2. Готовий `Dockerfile` та `docker-compose.yml` для старту сервісу в одну команду (`docker compose up -d`).
3. Вичерпний файл `README.md` із покроковою інструкцією для програміста магазину.
4. Готовий файл PHP-контролера OpenCart (`quiz_cart.php`) для швидкого імпорту в `catalog/controller/api/quiz_cart.php` (пакетне додавання `add_bulk`).
5. Файл конфігурації `.env.example` з коментарями для кожного параметра.
6. Очищений `.gitignore` для безпеки секретів та токенів.
