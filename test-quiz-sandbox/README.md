# Локальный тестовый квиз Race Expert

Изолированный прототип подбора до подключения к сайту. Использует локальный снимок 206 наборов «За потребами» и возвращает до трёх альтернатив.

## Запуск

Из этой папки выполните:

```sh
python3 server.py
```

Откройте <http://127.0.0.1:8765/>. Остановка — `Ctrl+C`. Сервер принимает только loopback IP и не доступен из локальной сети.

Чтобы пересобрать снимок из Wiki перед запуском:

```sh
python3 catalog_builder.py
python3 server.py
```

Зависимости — Python standard library. Квиз показывает цену на 2026-11-06; цена и наличие не обновляются с сайта.

## Какие ответы учитываются

- Обязательное назначение: точное совпадение тега `purpose`.
- Необязательные фильтры: спорт, тип набора, форма товара, формат старта, максимальная цена полного набора в UAH, размер обуви, отмеченный компонент, подтверждённое наличие.
- Точный тег спорта выше общего `not_sport_specific`; наборы с другим конкретным спортом исключаются.
- Неизвестный размер у набора не считается несовпадением, но карточка сообщает, что размер не указан. Записанный диапазон применяется строго.
- Строгий режим без кофеина требует `caffeine_status:confirmed_absent`. В текущем каталоге такого статуса нет, поэтому квиз возвращает `insufficient_data` вместо догадки.
- Неподдержанные ограничения (возраст, аллергены, вес покупателя, лекарства, точная дистанция и период/длительность приёма) API отвергает. Эти поля не представлены в форме; тег `3_months` может описывать абонемент, а не приём.
- Повторяемое ранжирование: точное совпадение спорта, указанное совпадение размера, цена, строка каталога. Кандидатов не дополняем несвязанными наборами.

Это временные правила для демонстрации, не утверждённые бизнес-правила. Ответы обрабатываются в памяти одного запроса; они не сохраняются. В прототипе нет подключения к сайту, корзине, Telegram, API каталога или БД. Ссылка на страницу набора служит источником и открывается только по действию пользователя. AI-оценок, заявлений о безопасности/эффективности и советов по приёму нет.

## Проверки и планы

- Запустить автоматические проверки: `python3 -m unittest discover -s tests -v`.
- [План проверок](TEST_PLAN.md) описывает сценарии и ограничения.
- [План реализации](IMPLEMENTATION_PLAN.md) фиксирует структуру прототипа.
- [`tickets/`](tickets/) — локальные test-only задачи, без публикации в трекер.

## Структура

- `catalog_builder.py` — парсер Wiki-анализа и генератор `catalog.json`.
- `matcher.py` — валидация входов, фильтрация и ранжирование.
- `server.py` — localhost-only JSON API и раздача страницы.
- `web/` — двуязычный экран квиза, стили и клиент.
- `tests/` — тесты снимка, логики подбора и API-обработчиков.
