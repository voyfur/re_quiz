# Полная техническая документация: Quiz Selection Engine

## 1. Назначение и концепция системы

**Race Expert Quiz Selection Engine** — интеллектуальная рекомендательная система для подбора готовых наборов спортивного питания, добавок и экипировки из каталога магазина [Race Expert](https://raceexpert.com.ua).

### Ключевые бизнес- и инженерные принципы:
1. **0 галлюцинаций и консервативная точность**: Алгоритм рекомендует наборы только на основании подтверждённых фактов (словесное позиционирование производителя/продавца и документированный состав). Не подтверждённые свойства никогда не додумываются.
2. **Абсолютная защита от тупиков (100% охват)**: Покупатель гарантированно получает подходящие варианты благодаря многоуровневой каскадной системе:
   - *Exact Matches* (полное совпадение);
   - *General Matches* (совпадение по ключевым факторам без противоречий);
   - *Near-Miss* (альтернативы с небольшим превышением бюджета +100–350 ₴);
   - *Floor Price Anchor* (стартовый базовый набор категории, если бюджет занижен).
3. **Двойная среда исполнения (Dual-Engine)**:
   - Python Backend (`draft_matcher.py` + `server.py`) для серверного API и тестирования;
   - Автономный Client-Side JavaScript (`client_matcher.js` + `public/index.html`), работающий без сервера даже при открытии локального файла (`file://`) в браузере.
4. **Объяснимый скоринг (Explainable AI)**: Каждая рекомендация сопровождается процентом соответствия (0–99%) и списком конкретных текстовых обоснований, почему набор подходит под выбранные ответы.

## 3. Четырёхслойная модель доказательной базы

В основе каждого решения лежит строгая таксономия, зафиксированная в `wiki/projects/quiz-set-audit.json`.

```
┌────────────────────────────────────────────────────────┐
│  Слой 1: Позиционирование продавца (Seller Families)   │  до 20% в скоринге
├────────────────────────────────────────────────────────┤
│  Слой 2: Недиспутируемый состав (Component Families)   │  до 15% в скоринге
├────────────────────────────────────────────────────────┤
│  Слой 3: Мягкие предпочтения покупателя (Preferences)   │  до 45% в скоринге
│  (спорт, тип товара, сценарий, время, место, форма)    │
├────────────────────────────────────────────────────────┤
│  Слой 4: Жёсткие ограничения (Constraints)             │  до 20% в скоринге
│  (максимальная цена в ₴, подтверждённый размер обуви)  │
└────────────────────────────────────────────────────────┘
```

### Допустимые категории потребностей (Goal Groups):
1. `running` — Біг і підготовка до стартів (`running_race_preparation`).
2. `training` — Силові тренування та м'язи (`strength_muscle_training`).
3. `hydration` — Гідратація та електроліти (`hydration_electrolytes`).
4. `food` — Спортивні перекуси та енергія (`portable_food_snacks`, `endurance_energy`).
5. `recovery` — Відновлення та сон (`recovery_fatigue`, `sleep_relaxation_stress`).
6. `outdoors` — Походи та кемпінг (`outdoor_travel_hiking`).
7. `gear` — Одяг та аксесуари (`foot_apparel_comfort`).
8. `daily` — Щоденна підтримка та вітаміни (`general_daily_nutrition`).
9. `gift` — Подарунковий набір (`gift_identity`).

## 4. Логика динамического опроса (Question Flow)

Квиз динамически выстраивает маршрут: покупатель видит **только актуальные вопросы**, зависящие от оставшихся кандидатов.

### Пошаговый сценарий:
- **Шаг 1: Главная спортивная задача (`goal_group`)**  
  Определяет первичный пул наборов. Если выбрано `running`, отбираются только наборы, позиционированные для бега.
- **Шаг 2–4: Уточняющие вопросы (генерируются динамически)**:
  - *Вид активности (`activity`)*: бег, велоспорт, походы, кроссфит, зал, йога.
  - *Ключевой класс товара (`component_class`)*: изотоники, спортивное питание, батончики, витамины, аксессуары, экипировка.
  - *Сценарий (`use_scenario`)*: подготовка к старту, тренировочный цикл, каждый день.
  - *Время и место (`use_timing`, `use_place`)*: до/после тренировки, на дистанции, работа/учёба, поход/дорога.
  - *Форма продукта (`product_form`)*: гели, батончики, порошок, стики, капсулы, таблетки.
  - *Размер обуви/носков (`shoe_size`)*: задается **только** если в оставшемся пуле есть товары с подтвержденным размерным рядом.
  - *Клубный абонемент (`membership`)*: задается в ветках, где есть наборы Race Expert Club (например, тренировки и подарки).
- **Шаг 5: Бюджет (`max_price_uah`)**:
  - На экран выводится **Dynamic Price Hint**: подсказка реальной вилки цен по оставшимся наборам (`"Підходящі набори за вашими критеріями: від {min} до {max} ₴"`).
  - Поле необязательное: покупатель может оставить его пустым или нажать «Не має значення».

## 5. Математическая модель Match Confidence Score (0–99%)

Итоговый балл соответствия вычисляется по прозрачной формуле:

$$\text{Score} = \text{Score}_{\text{evidence}} (0..35) + \text{Score}_{\text{preferences}} (0..45) + \text{Score}_{\text{constraints}} (0..20)$$

### 1. Слой доказательств (до 35%):
- $+20\%$: Заявлено прямое позиционирование продавца (`seller_families`).
- $+15\%$: Наличие в составе подтвержденного компонента задачи (`component_families`).
- $-5\%$: Штраф, если в карточке есть пометка `conflict_review_required`.

### 2. Слой предпочтений покупателя (до 45%):
- При отсутствии активных предпочтений начисляются базовые $45\%$.
- При наличии ответов каждый подтвержденный ответ даёт $1.0$ балла, частично подтвержденный (unknown в каталоге) — $0.55$ балла.
- Итоговая доля масштабируется: $\text{round}\left(45 \times \frac{\sum \text{points}}{N_{\text{active}}}\right)$.

### 3. Слой ограничений бюджета и размера (до 20%):
- Размер: $+10\%$ если размер не требовался или совпал; $+5\%$ если размер в карточке неизвестен.
- Бюджет: $+10\%$ если цена укладывается в бюджет; $+5\%$ если бюджет не задавался; пропорциональное снижение при Near-Miss.

### Границы типов соответствия:
| Тип матча | Диапазон скора | Описание |
|---|:---:|---|
| **Exact Match** | **88% – 99%** | Полное подтверждение всеми слоями без расхождений. |
| **General Auto** | **72% – 87%** | Нет прямых противоречий, но часть вторичных деталей не зафиксирована в каталоге. |
| **Near-Miss** | **60% – 84%** | Идеально подходит по параметрам, но слегка превышает бюджет (+100–350 ₴). |
| **Floor Anchor** | **45% – 75%** | Базовый минимальный набор категории при сильно заниженном бюджете. |
| **Relaxed Match** | **35% – 68%** | Показан по отдельному запросу пользователя с ослаблением мягких предпочтений. |

## 6. Пользовательский интерфейс и интерактивные возможности

1. **Двуязычность на лету (УКР / РУС)**:  
   Переключение языка доступно в любой момент в шапке квиза (`УКР` / `РУС`). Тексты вопросов, опций, бейджей и карточек товаров обновляются мгновенно без потери уже выбранных ответов.
2. **8-направленный свободный ресайз виджета**:  
   Виджет можно свободно растягивать за любую сторону и угол:
   - Влево / вправо (`handle-w`, `handle-e`);
   - Вверх / вниз (`handle-n`, `handle-s`);
   - По диагоналям (`handle-se`, `handle-sw`, `handle-ne`, `handle-nw`);
   - Быстрые пресеты: кнопки **S** (620px), **M** (780px), **L** (980px).
3. **Автономность (Zero-Dependency)**:  
   Страница `public/index.html` и `quiz.html` включает в себя инлайновые стили Tailwind CDN и скомпилированные массивы каталога. Ее можно отправить клиенту файлом и запустить двойным кликом в браузере без веб-сервера.

## 7. Автономный скилл онбординга товаров (`race-expert-kit-onboarding`)

Скилл расположен в [`.agents/skills/race-expert-kit-onboarding/`](file:///Users/anatoly/Workspace/03_Business/WORK/Race%20Expert/Quiz%20RE/.agents/skills/race-expert-kit-onboarding/SKILL.md) и предназначен для добавления новых товаров по веб-ссылке.

### Автоматический цикл:
1. `fetch_and_parse_kit.py`: Скачивает HTML, вытаскивает артикул, цену, состав, генерирует исследовательские задачи `research_tasks`.
2. Поиск в сети (`search_web`): Закрывает белые пятна по дозировкам, формам фасовки и составам.
3. `normalize_kit_data.py`: Проверяет соответствие нормативным словарям (`references/controlled_vocabularies.md`).
4. `ingest_kit.py`: Назначает уникальный `catalog_row` и `set_id`, пополняет `catalog.json` и `quiz-set-audit.json`, автоматически пересобирает клиентские бандлы и обновляет HTML-страницы.
5. `audit_new_kit.py`: Эмулирует поисковые запросы к новому набору и подтверждает его присутствие в выдаче с высоким процентом уверенности.

## 8. Подсистема онлайн-проверки остатков и цен (Stock Verification Subsystem)

Интеллектуальная система верификации наличия и актуальной стоимости наборов перед показом рекомендаций покупателю.

### 8.1. Архитектура и безопасность соединения
- **Модуль**: `test-quiz-sandbox/stock_checker.py`.
- **Маршрут**: Подключение выполняется исключительно с VPS автоматизации **VPS-61125** (`185.25.119.96`) на порт `3306` MySQL endpoint (`173.242.63.36`).
- **TLS**: Обязательный **TLS 1.3** (`TLS_AES_256_GCM_SHA384`, MySQL 8.0.45-36). Проверка самоподписанного сертификата отключена по прямому разрешению пользователя для read-only аудита; запрещён переход на plaintext.
- **Двухрежимная работа**:
  - На VPS: прямое socket-соединение с БД.
  - На локальной машине разработчика: автоматический фоновый SSH-туннель через VPS-61125.
  - Офлайн: мягкий fallback на каталог-снимок без сбоев интерфейса.
- **Безопасность**: Пароли не попадают в логи, shell history или таблицу процессов (передаются через защищённый stdin/env).

### 8.2. Правило доступности в OpenCart
На основе аудита базы `raceexpertcomua` установлено:
```python
is_in_stock = (status == 1 and quantity > 0)
```
- `quantity > 0` и `status == 1`: товар физически доступен на складе (на сайте активна кнопка «Купить»).
- `quantity <= 0` или `status == 0`: товар отсутствует (в OpenCart отображается `stock_status_id=5` «Немає в наявності»).

### 8.3. Логика подбора при проверке наличия (Stock-Aware Matcher)
1. **Приоритет наличия при ранжировании**:
   В `_rank_candidate_entries` первым критерием сортировки является `-int(in_stock)`. Это гарантирует, что кандидаты в наличии всегда рекомендуются выше временно отсутствующих позиций с аналогичным скором.
2. **Бесшовный Next Best Match**:
   Если топ-набор закончился на складе, алгоритм автоматически повышает следующий лучший вариант из совместимого пула.
3. **Синхронизация живой цены**:
   Если цена на сайте изменилась относительно снимка, квиз показывает реальную актуальную цену магазина с пометкой в карточке.
4. **Интерфейс и бейджи**:
   - Зелёный бейдж: `● В наявності` / `● В наличии`
   - Красный бейдж: `○ Немає в наявності` / `○ Нет в наличии`
   - Информационная сноска: `Склад перевірено онлайн`.

### 8.4. API эндпоинты
- `POST /api/check-stock`: `{"skus": ["RE88955", "RE11819"]}` -> возвращает статус наличия, остаток и цену.
- `POST /api/draft/recommend`: при передаче `"verify_stock": true` автоматически запрашивает склад по кандидатам и обогащает ответ полем `stock_info`.
